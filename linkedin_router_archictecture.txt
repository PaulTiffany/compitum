# LinkedIn Engagement Router: Architecture Specification

## Overview

Extension of `compitum` to route LinkedIn draft posts to engagement quality buckets using the existing SPD metric learning infrastructure.

## Core Principle

**Same router, different buckets:**
- Current: `Prompt → Router → [GPT-4 | Claude | Llama]`
- LinkedIn: `Draft Post → Router → [Great | Good | Needs-Work | Off-Brand]`

## Data Format

### Historical Post Data (`posts_history.jsonl`)

Each line is a JSON object representing one historical post:

```json
{
  "post_id": "urn:li:share:7012345678901234567",
  "text": "Excited to share my thoughts on AI ethics and the future of responsible innovation...",
  "timestamp": "2024-03-15T09:23:00Z",
  "metrics": {
    "impressions": 2340,
    "likes": 187,
    "comments": 23,
    "shares": 12,
    "engagement_rate": 0.0949
  },
  "metadata": {
    "has_media": true,
    "media_type": "image",
    "char_count": 284,
    "hashtag_count": 3,
    "has_question": false,
    "hour_of_day": 9,
    "day_of_week": "Friday"
  },
  "bucket": "great-post"
}
```

**Bucket assignment** (done during preprocessing):
- `engagement_rate = (likes + 2*comments + 3*shares) / impressions`
- Weighted to value comments/shares more than passive likes

## New Code Components

### 1. Data Loader (`compitum/linkedin/data_loader.py`)

```python
"""Load and preprocess LinkedIn post history for router training."""
import json
from pathlib import Path
from typing import List, Dict
import numpy as np

class LinkedInDataLoader:
    def __init__(self, user_id: str, data_dir: Path):
        self.user_id = user_id
        self.data_dir = data_dir / "linkedin_users" / f"user_{user_id}"
        
    def load_posts(self) -> List[Dict]:
        """Load historical posts from JSONL file."""
        posts = []
        posts_file = self.data_dir / "posts_history.jsonl"
        
        with open(posts_file, 'r') as f:
            for line in f:
                posts.append(json.loads(line))
        
        return posts
    
    def prepare_training_data(self, posts: List[Dict]):
        """
        Convert posts to format expected by compitum router.
        
        Returns:
            prompts: List[str] - post text
            labels: List[str] - bucket names
            metadata: List[Dict] - additional features
        """
        prompts = [p['text'] for p in posts]
        labels = [p['bucket'] for p in posts]
        metadata = [p['metadata'] for p in posts]
        
        return prompts, labels, metadata
    
    def compute_engagement_rate(self, post: Dict) -> float:
        """
        Weighted engagement rate.
        Likes=1x, Comments=2x, Shares=3x (more valuable interactions)
        """
        m = post['metrics']
        weighted_engagement = (
            m['likes'] + 
            2 * m['comments'] + 
            3 * m['shares']
        )
        return weighted_engagement / m['impressions']
```

### 2. Bucket Assigner (`compitum/linkedin/bucket_assigner.py`)

```python
"""Assign posts to engagement quality buckets."""
import numpy as np
from typing import List, Dict

class BucketAssigner:
    def __init__(self, config: Dict):
        self.buckets = config['buckets']
        
    def assign_bucket(self, post: Dict, brand_coherence: float) -> str:
        """
        Assign post to bucket based on engagement + brand coherence.
        
        Args:
            post: Post with engagement metrics
            brand_coherence: Score from 0-1 (from KDE coherence check)
        
        Returns:
            Bucket name
        """
        engagement_rate = post['metrics']['engagement_rate']
        
        # Find matching bucket (priority order matters)
        for bucket in self.buckets:
            criteria = bucket['criteria']
            if (engagement_rate >= criteria['engagement_rate_min'] and
                brand_coherence >= criteria['brand_coherence_min']):
                return bucket['name']
        
        # Fallback
        return "needs-work"
    
    @staticmethod
    def compute_percentile_thresholds(posts: List[Dict], percentiles=[25, 50, 75]):
        """
        Compute engagement rate percentiles from historical data.
        Used to set bucket thresholds automatically.
        """
        engagement_rates = [p['metrics']['engagement_rate'] for p in posts]
        return np.percentile(engagement_rates, percentiles)
```

### 3. LinkedIn API Client (`compitum/linkedin/api_client.py`)

```python
"""Optional: Fetch LinkedIn data via API."""
import requests
from typing import Dict, List
from datetime import datetime

class LinkedInAPIClient:
    """
    Wrapper for LinkedIn API v2.
    Requires OAuth2 authentication and approved API access.
    """
    
    BASE_URL = "https://api.linkedin.com/v2"
    
    def __init__(self, access_token: str):
        self.access_token = access_token
        self.headers = {
            "Authorization": f"Bearer {access_token}",
            "Content-Type": "application/json"
        }
    
    def fetch_user_posts(self, user_id: str, limit: int = 100) -> List[Dict]:
        """
        Fetch user's post history with engagement metrics.
        
        NOTE: This requires LinkedIn Partner API access.
        For most users, manual export via LinkedIn UI is easier.
        """
        endpoint = f"{self.BASE_URL}/ugcPosts"
        params = {
            "q": "authors",
            "authors": f"urn:li:person:{user_id}",
            "count": limit
        }
        
        response = requests.get(endpoint, headers=self.headers, params=params)
        response.raise_for_status()
        
        posts = response.json()['elements']
        return self._parse_posts(posts)
    
    def _parse_posts(self, raw_posts: List[Dict]) -> List[Dict]:
        """Convert LinkedIn API response to our format."""
        parsed = []
        for post in raw_posts:
            parsed.append({
                "post_id": post['id'],
                "text": post['specificContent']['com.linkedin.ugc.ShareContent']['shareCommentary']['text'],
                "timestamp": post['created']['time'],
                "metrics": self._fetch_post_metrics(post['id']),
                "metadata": self._extract_metadata(post)
            })
        return parsed
    
    def _fetch_post_metrics(self, post_id: str) -> Dict:
        """Fetch engagement metrics for a specific post."""
        endpoint = f"{self.BASE_URL}/socialActions/{post_id}"
        response = requests.get(endpoint, headers=self.headers)
        data = response.json()
        
        return {
            "impressions": data.get('impressionCount', 0),
            "likes": data.get('likeCount', 0),
            "comments": data.get('commentCount', 0),
            "shares": data.get('shareCount', 0)
        }
```

### 4. Feedback Formatter (`compitum/linkedin/feedback_formatter.py`)

```python
"""Format router output for user-friendly display."""
from typing import Dict, List
from rich.console import Console
from rich.table import Table
from rich.panel import Panel

class FeedbackFormatter:
    def __init__(self, config: Dict):
        self.config = config
        self.console = Console()
    
    def format_routing_result(self, 
                            draft_text: str,
                            routed_bucket: str,
                            confidence: float,
                            similar_posts: List[Dict]) -> str:
        """
        Create rich formatted output for router decision.
        
        Args:
            draft_text: User's draft post
            routed_bucket: Bucket name from router
            confidence: Router confidence (0-1)
            similar_posts: Top-3 similar historical posts
        """
        bucket_config = next(b for b in self.config['buckets'] 
                           if b['name'] == routed_bucket)
        
        # Main recommendation panel
        panel = Panel(
            f"[bold]{bucket_config['recommendation']}[/bold]\n\n"
            f"Confidence: {confidence:.1%}\n"
            f"Predicted Engagement: {self._estimate_engagement(routed_bucket)}",
            title=f"Routing Result: {routed_bucket}",
            border_style=bucket_config['color']
        )
        self.console.print(panel)
        
        # Similar posts table
        if similar_posts:
            table = Table(title="Similar High-Performing Posts")
            table.add_column("Post Preview", style="cyan")
            table.add_column("Engagement", justify="right", style="green")
            
            for post in similar_posts[:3]:
                preview = post['text'][:60] + "..."
                engagement = f"{post['metrics']['engagement_rate']:.1%}"
                table.add_row(preview, engagement)
            
            self.console.print(table)
    
    def _estimate_engagement(self, bucket: str) -> str:
        """Estimate engagement range based on bucket."""
        ranges = {
            "great-post": "High (75-95th percentile)",
            "good-post": "Moderate (45-75th percentile)",
            "needs-work": "Low (<45th percentile)",
            "off-brand": "Uncertain (inconsistent with history)"
        }
        return ranges.get(bucket, "Unknown")
```

### Script 1: Fetch Data (`scripts/fetch_linkedin_data.py`)

```python
"""
Download LinkedIn post history for a user.

NOTE: LinkedIn API access is restrictive. Most users will need to:
1. Go to LinkedIn Settings > Data Privacy > Get a copy of your data
2. Download "Posts" CSV
3. Convert to our JSONL format using this script
"""
import click
import pandas as pd
import json
from pathlib import Path

@click.command()
@click.option('--csv-path', type=click.Path(exists=True), 
              help='Path to LinkedIn data export CSV')
@click.option('--user-id', type=str, required=True)
@click.option('--output-dir', type=click.Path(), default='data/linkedin_users')
def fetch_data(csv_path, user_id, output_dir):
    """Convert LinkedIn CSV export to training data format."""
    
    # Read LinkedIn CSV
    df = pd.read_csv(csv_path)
    
    # Create user directory
    user_dir = Path(output_dir) / f"user_{user_id}"
    user_dir.mkdir(parents=True, exist_ok=True)
    
    # Convert to JSONL
    posts = []
    for _, row in df.iterrows():
        post = {
            "post_id": row['Post ID'],
            "text": row['Post Content'],
            "timestamp": row['Posted Date'],
            "metrics": {
                "impressions": row['Impressions'],
                "likes": row['Likes'],
                "comments": row['Comments'],
                "shares": row['Shares'],
                "engagement_rate": (row['Likes'] + 2*row['Comments'] + 3*row['Shares']) / row['Impressions']
            },
            "metadata": {
                "char_count": len(row['Post Content']),
                "has_media": pd.notna(row.get('Media Type')),
                # Add more metadata extraction
            }
        }
        posts.append(post)
    
    # Save as JSONL
    output_path = user_dir / "posts_history.jsonl"
    with open(output_path, 'w') as f:
        for post in posts:
            f.write(json.dumps(post) + '\n')
    
    click.echo(f"✓ Saved {len(posts)} posts to {output_path}")

if __name__ == '__main__':
    fetch_data()
```

### Script 3: Train Router (`scripts/train_linkedin_router.py`)

```python
"""Train compitum router on LinkedIn engagement data."""
import click
from pathlib import Path
from compitum.router import Router
from compitum.linkedin.data_loader import LinkedInDataLoader

@click.command()
@click.option('--user-id', type=str, required=True)
@click.option('--data-dir', type=click.Path(), default='data')
def train_router(user_id, data_dir):
    """Train SPD metric router on user's LinkedIn history."""
    
    data_dir = Path(data_dir)
    user_dir = data_dir / "linkedin_users" / f"user_{user_id}"
    config_path = user_dir / "config.yaml"
    
    # Load data
    loader = LinkedInDataLoader(user_id, data_dir)
    posts = loader.load_posts()
    prompts, labels, metadata = loader.prepare_training_data(posts)
    
    click.echo(f"Training on {len(prompts)} posts...")
    
    # Initialize router (reuse existing Router class!)
    router = Router(config_path)
    
    # Train SPD metric
    # The Router.fit() method already exists - just pass different data!
    router.fit(
        prompts=prompts,      # Post text
        targets=labels,       # Bucket names
        metadata=metadata     # Optional: time, media info
    )
    
    # Save trained router
    output_path = user_dir / "trained_router.pkl"
    router.save(output_path)
    
    click.echo(f"✓ Trained router saved to {output_path}")
    
    # Validation: Route some test posts
    click.echo("\nValidation on random posts:")
    import random
    for post in random.sample(posts, min(5, len(posts))):
        predicted = router.route(post['text'])
        actual = post['bucket']
        match = "✓" if predicted == actual else "✗"
        click.echo(f"{match} '{post['text'][:50]}...'")
        click.echo(f"  Predicted: {predicted}, Actual: {actual}")

if __name__ == '__main__':
    train_router()
```

```python
import pytest

def test_bucket_assignment_thresholds():
    """Test that posts are assigned to correct buckets."""
    config = {
        "buckets": [

    # Low engagement → needs-work
    low_post = {"metrics": {"engagement_rate": 0.02}}
    assert assigner.assign_bucket(low_post, brand_coherence=0.7) == "needs-work"

def test_percentile_computation():
    """Test automatic threshold computation."""
    posts = [
        {"metrics": {"engagement_rate": 0.05}},
        {"metrics": {"engagement_rate": 0.10}},
        {"metrics": {"engagement_rate": 0.15}},
        {"metrics": {"engagement_rate": 0.20}}
    ]
    
    p25, p50, p75 = BucketAssigner.compute_percentile_thresholds(posts, [25, 50, 75])
    
    assert p25 == pytest.approx(0.0625, rel=0.1)
    assert p50 == pytest.approx(0.125, rel=0.1)
```

```python
class Router:

    def get_confidence(self, text: str, bucket: str) -> float:
        """
        NEW: Return confidence score for routing decision.
        Computed as probability mass in metric space around bucket center.
        """
        embedding = self.embedder.embed(text)
        return self.metric.compute_confidence(embedding, bucket)
    
    def find_similar(self, text: str, top_k: int = 3) -> List[Dict]:
        """
        NEW: Find k most similar posts from training history.
        Uses metric distance in SPD space.
        """
        embedding = self.embedder.embed(text)
        distances = [
            (post, self.metric.distance(embedding, post['embedding']))
            for post in self.training_data
        ]
        distances.sort(key=lambda x: x[1])
        return [post for post, _ in distances[:top_k]]
```

**Your existing router already does exactly what we need:**

```python
# Current LLM router logic:

    "gpt-4": metric.distance(embedding, gpt4_performance_region),
```

**LinkedIn router logic (identical!):**

The **only** difference is what the "regions" represent:
- LLM router: Regions where each model performs well

Both train the same SPD metric to learn: **"What input patterns lead to what outcomes?"**

### Mathematical Equivalence

The SPD metric learns a Riemannian distance function:

```
d_M(x, y) = sqrt((x - y)^T M (x - y))
```

Where `M` is a symmetric positive-definite matrix learned from data.

**For LLM routing:**
- `x` = prompt embedding
- `y` = centroid of "good performance" region for a model
- `M` learned to make high-quality prompts "close" to their best model

**For LinkedIn routing:**
- `x` = post embedding
- `y` = centroid of "high engagement" posts
- `M` learned to make engaging posts "close" to high-engagement region

**Same math, different semantics!**

### Why Buckets Instead of Regression?

You asked about routing to buckets vs. predicting a continuous engagement score. Here's why buckets are better:

**Option A: Regression (Bad Fit)**
```python
predicted_engagement = model.predict(post_embedding)  # Returns 0.0-1.0
# Problem: User gets "0.073" - what does that mean?
# No clear action item
```

**Option B: Routing to Buckets (Good Fit)**
```python
bucket = router.route(post_embedding)  # Returns "great-post"
recommendation = bucket_config[bucket]["recommendation"]
# User gets: "✓ Post this now!" - clear action
```

**Additional benefits of bucketing:**
1. **Interpretability**: "Great post" is clearer than "0.087 engagement rate"
2. **Robustness**: Bucket boundaries can be user-specific percentiles
3. **Actionability**: Each bucket maps to a clear recommendation
4. **Your router already does this**: No new architecture needed

### Handling Brand Coherence

One unique aspect: LinkedIn posts need "brand coherence" (on-brand vs. off-brand).

**Implementation using KDE Coherence (already in compitum!):**

```python
# During training, build KDE over high-engagement posts
kde = KDE(bandwidth=0.1)
kde.fit([post['embedding'] for post in posts if post['bucket'] == 'great-post'])

# When routing new post
def compute_brand_coherence(draft_embedding):
    """
    Coherence = probability density under KDE of successful posts.
    Low density = "this is unlike your usual content"
    """
    return kde.score_samples([draft_embedding])[0]

# Use in bucket assignment
coherence = compute_brand_coherence(draft_embedding)
if engagement_high and coherence_high:
    return "great-post"
elif engagement_high and coherence_low:
    return "good-but-off-brand"  # High engagement but unusual style
```

This is **exactly** what your `metric-aware KDE coherence` in the README already does!

### Constraint Handling Examples

Your shadow pricing mechanism handles constraints like:
- LLM router: "Don't exceed $100/day API budget"
- LinkedIn router: "Don't post more than 2x per day"

**Example constraint configuration:**

```yaml
constraints:
  # Hard constraints (must satisfy)
  max_posts_per_day: 2
  min_hours_between_posts: 4
  
  # Soft constraints (preferences)
  preferred_posting_hours: [8, 9, 10, 17, 18]
  preferred_days: ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"]
  
  # Shadow prices (how much to penalize violations)
  shadow_price_off_hours: 0.1   # Slight penalty for posting at 2am
  shadow_price_weekend: 0.05    # Slight penalty for weekend posts
```

**Router applies constraints:**

```python
# Pseudo-code in router.route()
base_score = metric.distance(embedding, bucket_centroid)

# Apply constraint penalties
if current_time.hour not in config['preferred_posting_hours']:
    base_score += config['shadow_price_off_hours']

if posts_today >= config['max_posts_per_day']:
    return "rate-limited"  # Hard constraint violated

final_score = base_score
return best_bucket_considering_constraints(final_score)
```

## Risk Analysis

### Technical Risks

**Risk 1: Insufficient training data**
- Mitigation: Require minimum 50 posts to train
- Fallback: Use generic heuristics until enough data

**Risk 2: LinkedIn API access**
- Mitigation: Support manual CSV export (most realistic)
- Alternative: Third-party API services (Unipile, Phyllo)

**Risk 3: Overfitting to past patterns**
- Mitigation: Online learning updates as audience evolves
- Monitoring: Track prediction accuracy over time

### User Experience Risks

**Risk 1: "Off-brand" bucket feels judgmental**
- Mitigation: Reframe as "experimental" or "new direction"
- UX: Show it as exploration opportunity, not failure

**Risk 2: Predictions are wrong**
- Mitigation: Show confidence intervals, not point estimates
- Transparency: "73% confident" vs. "definitely will succeed"

**Risk 3: User posts anyway despite "needs-work" warning**
- Solution: Track these to improve model
- Feature: "I posted anyway" feedback button

### Ethical Considerations

**Concern 1: Encouraging "engagement bait"**
- Response: Router learns from user's authentic voice
- Guardrail: Flag if suggestions drift toward clickbait patterns

**Concern 2: Privacy of LinkedIn data**
- Response: All data stays local, never uploaded
- Architecture: User-specific models, no aggregation

**Concern 3: Over-optimization kills authenticity**
- Response: Brand coherence metric preserves voice
- UX: Mark "on-brand" as equally important as "high engagement"
